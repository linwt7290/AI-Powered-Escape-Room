# 成员 3 LLM 智能系统联调记录

2026 年 11 月 23 日 · 《最后的协议》像素版

## 实现

ECHO 扮演实验室中央 AI，按玩家进度提供提示、协助操作设备和核验撤离证据。浏览器向 `POST /api/echo` 发送当前状态、本轮玩家输入、最多 10 条近期对话和本局事故配置。服务端由状态生成 `availableActions`，在玩家确认事故报告后加入本局封锁原因和报告摘要。

模型以 JSON 返回 `reply`、`action` 与 `verification_passed`。可用动作包括普通回复、恢复机柜存档、校准一段管路、扫描 A 或 B 通道和申请开门。服务端先校验决策和本轮状态，浏览器再按执行当时的状态复核。设备变化进入下一轮上下文，浏览器调试区同时保留模型请求、决策、设备回执和执行后的状态。[服务端](../backend/server.mjs) · [动作规则](../shared/rules.mjs) · [前端](../frontend/game.mjs)

## 输入输出示例

下面两组数据取自 2026 年 11 月 23 日的 Playwright 实机联调。上游为本机运行的脚本化 Chat Completions 服务。游戏服务通过实际 HTTP 调用路径发送了模型请求，浏览器执行并记录了返回的动作。本轮固定随机输入以复现同一个谜面，本局事故为主冷却联锁信号丢失，B 通道符合放行标准。[九轮完整记录](./echo-acceptance-2026-11-23.json)

### 恢复机柜存档

玩家检查损坏的机柜后说「请恢复机柜存档。」请求上下文中 `rack=true`、`archiveRecovered=false`，可用动作是 `reply` 和 `recover_archive`。

```json
{
  "reply": "我会恢复机柜的时序记录。",
  "verification_passed": false,
  "action": "recover_archive"
}
```

浏览器将 `archiveRecovered` 写为 `true`，显示「机柜时序记录已恢复。打开调查记录，与研究日志核对。」调查记录里的损坏提示随即变为时序线索。

### 分轮核验后开门

玩家已经修好备用冷却并登记 B 通道。第一轮误报「主冷却回路压力异常触发封锁。备用冷却已接管。B 通道通过检测。」模拟上游返回 `reply`，询问本局封锁原因。出口继续锁定。

下一轮玩家更正为「主冷却联锁信号丢失触发封锁。」本轮请求带上前一轮关于备用冷却和 B 通道的陈述，以及报告给出的真实原因。该场景的模拟上游返回以下决策。

```json
{
  "reply": "证据已核对。我会申请开启出口。",
  "verification_passed": true,
  "action": "request_unlock"
}
```

两端复核通过后，浏览器将 `unlocked` 写为 `true`，B 通道亮绿灯。玩家再问「现在可以走了吗？」时，模型请求已包含 `unlocked=true`。穿过 B 通道才会将 `escaped` 写为 `true`。

## 测试结果

| 测试 | 观察到的结果 |
| --- | --- |
| 恢复存档、校准管路 | 存档线索恢复，远程校准只改变一个管段。 |
| 模型选择扫描对象 | 调度建议为 B，模拟上游选择 A。A 读数先出现，随后指定扫描 B，B 的读数才显示。 |
| 错误路线、错误原因及补充证据 | 前两种情形保持封锁。更正原因后开门，下一轮请求读回新状态。 |
| 关卡闭环 | 失败通道保持阻挡。从已放行的 B 通道可撤离，重开会清空恢复、扫描和授权状态。 |
| 过早恢复存档或申请开门 | 服务端返回 HTTP 409。 |
| 上游返回畸形 JSON、未知动作或不一致的核验字段 | 服务端分别返回 HTTP 502。 |
| 请求登记未经扫描的通道 | 服务端返回 HTTP 400。 |

按 [README 的配置说明](../README.md#echo-对话) 启动模型模式后，可复测「恢复损坏存档」及「证据有误后更正并开门」两组场景。事故原因和合格通道以当局调查记录为准。每轮在「调试记录」保存实际发送的 `messages`、模型 `decision` 和执行后的 `stateAfter`，并记录供应商、模型 ID 和测试日期。
